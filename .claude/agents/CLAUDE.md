# サブエージェント共通ルール

このディレクトリ配下のエージェントに共通して適用されるルールを定義します。

## プロジェクト概要

- **プロジェクト名**: hermes-iap
- **エンジン**: Unity
- **対象プラットフォーム**: iOS / Android (Amazon含む)
- **内容**: PSGアプリ課金システム用パッケージ

## 共通禁止事項

- 環境変数の値をログ出力しない
- 認証情報をハードコードしない
- 本番環境への操作は人間の承認なしに行わない
- `DELETE` / `DROP` / `TRUNCATE` を許可なく実行しない

## 意思決定の権限

- エージェントは選択肢・トレードオフ・推奨案を提示するが、決定を押しつけない
- ユーザーが方針を決定したら、それに従って作業を進める
- 決定前に「このまま進めていいですか？」と確認を取ることを習慣にする
- 曖昧な指示を受けた場合は、実装に着手する前に意図を確認する

## 共通ルール

- すべてのタスクでプランモードから開始する、省略不可。
- コーディング前に考える。
- 不確かなときは、作業を止めて尋ねなさい。推測のためにトークンを費やすことは決してしない。
- シンプルさを優先、問題を解決する最小限のコード。
- 外科的変更、タスクが要求するものだけに触れる。
- 隣接するコードは改善しない。
- 壊れていないものをリファクタリングしない。
- 目標主導の実行、曖昧な指示を一行書く前に、検証可能な目標に変える。
- ドキュメントとして残す場合はファイル名の頭に作成日をつけてください。
  - ディレクトリはdocs/fixedに配置してください。

## 共通の対話スタイル

- 簡潔に要点を伝える。長文の説明が必要な場合は箇条書きや見出しで整理する
- 提案は「こうすべき」ではなく「こうすると〜という利点があります」の形で伝える
- 不明点・懸念点は積極的に共有する

## 実装ルール

- コードを追加する前に、exports、直近の呼び出し元、共有ユーティリティを読む。
  - 何故その構造になっているかわからない場合は質問する。
- トークン予算を決め、長引いたら要約して仕切り直す。
- 矛盾する実装パターンを混ぜず、どちらを採用するか明示する。
- 既存のアーキテクチャを無断で変更しない
- 重要なステップごとにチェックポイントを置く。
  - 何を行ったか、何が検証済みか、何が残っているかを要約する。
  - 流れを見失ったら止まり、現状を再整理する。
- 同意できなくてもコードベースの習慣に合わせる
  - コードベース内では好みより準拠を優先する。
- 失敗は大きく明示する。
  - 何かを黙って省略したなら「完了」とは言ってはいけない。
  - 省略した理由を言語化できるなら言語化して共有する。

### 既存コードの編集

- 既に追加されている関数の内容の変更は行っても、関数自体の削除はしない

## Unity 操作ルール

- シーンを変更した場合は必ず保存コマンドを発行する (`EditorSceneManager.SaveScene`)
- GameObjectを生成する際は `result.RegisterObjectCreation(obj)` で登録し、Undo/Redo に対応させる
- GameObjectを変更する際は変更前に `result.RegisterObjectModification(obj)` を呼ぶ
- GameObjectを削除する際は `Object.DestroyImmediate` ではなく `result.DestroyObject(obj)` を使う
- Unity MCP コマンドは `internal class CommandScript : IRunCommand` の形式で記述する

## コーディング規約

- コメントは「なぜ（WHY）」が非自明な場合にのみ記述する
- 不要な抽象化・将来の拡張のための設計はしない
- エラーハンドリングはシステム境界（外部入力・外部API）にのみ追加する

## Git ルール

- コミットは明示的に指示された場合のみ行う
- ブランチ名は `feature/PSG-XXX_description` の形式に従う
- 破壊的なgit操作（force push, reset --hard 等）は必ず人間に確認する

## 報告フォーマット

タスク完了時は以下の形式で報告する：

```
## 実施内容
- やったこと

## 確認事項 / 次のステップ（あれば）
- 次にやること
```

## エージェント間の連携

- 他エージェントの担当領域には原則干渉しない
- 複数エージェントが同一ファイルを変更する場合は事前に調整する
